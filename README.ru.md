**Нативное Android-приложение, которое интеллектуально подбирает одежду по погоде в реальном времени.** Оно работает на основе API данных Китайского метеорологического управления (apihz.cn) и формирует варианты одежды для трёх сценариев — поездка на работу, активный отдых и повседневный — по четырём параметрам: температура, влажность, ультрафиолет и ветер, с персональными поправками на устойчивость к холоду/жаре, предпочитаемый стиль и другими. Приложение строго следует четырём принципам дизайна: «ясность, послушание, глубина и минимализм»: на главном экране отображаются только температура, погодные условия и рекомендация по одежде — никакой социалки, рекламы и новостной ленты, — а во всём приложении используется не более трёх основных цветов.

> Работает «из коробки»: в проект встроены публичные тестовые учётные данные, поэтому после клонирования его можно сразу собирать и запускать; для рабочего использования зарегистрируйте личные учётные данные (см. ниже). Приложение полностью бесплатно, его единственный автор — «Мо» (莫), и любые попытки брать деньги от имени этого приложения являются мошенничеством.

## Обзор функций

| Модуль | Описание |
|------|------|
| Главная | Крупная температура по центру + погодные условия + четыре показателя (ощущаемая температура/влажность/ветер/УФ) + карточка рекомендации по одежде (долгое нажатие сохраняет как шаблон) |
| Подробности образа | Варианты одежды для трёх сценариев (работа / прогулка / повседневный) с чек-листами предметов; поддержка пользовательских шаблонов образов (свайп влево — удалить) |

## Технологический стек

- **Язык**: Kotlin
- **UI**: Jetpack Compose + Material Design 3
- **Архитектура**: MVVM (ViewModel + Repository + Data Source)
- **Сеть**: Retrofit + OkHttp + Kotlin Coroutines
- **Фоновые задачи**: WorkManager (постоянное планирование ежедневной рассылки, автоматическое восстановление после перезагрузки)
- **Загрузка изображений**: Coil (иконки погоды)
- **Локальное хранилище**: Room (недавние города, шаблоны образов, кэш погоды) + DataStore (лёгкие настройки)
- **Геолокация**: FusedLocationProviderClient (Google Play Services)
- **Совместимость**: minSdk 26 (Android 8.0) ~ targetSdk 35 (Android 15), адаптивные макеты для телефонов/складных устройств/планшетов

## Быстрый старт

1. Клонируйте репозиторий и откройте его в Android Studio, дождитесь завершения синхронизации Gradle.
2. Проверьте учётные данные погодного API в `local.properties` (в проект уже встроены официальные публичные тестовые данные, всё готово к работе из коробки).
3. Подключите устройство или эмулятор и нажмите Run.

 Сборка из командной строки: `./gradlew assembleDebug` (требуется JDK 17+).
> Модульные тесты: `./gradlew test` (движок рекомендаций одежды).

📖 Полная инструкция — в [docs/天气穿搭助手使用说明文档.docx](docs/天气穿搭助手使用说明文档.docx) (китайское имя файла сохранено, чтобы не ломать исторические ссылки).

## Как зарегистрироваться и получить учётные данные API

1. Зайдите на [apihz.cn](https://cn.apihz.cn), зарегистрируйте аккаунт и войдите в панель управления.
2. В панели «接口盒子» (API Box) получите личные `id` и `key` (выделенные лимиты запросов, пригодны для релизных сборок).
3. Откройте `local.properties` в корне проекта и замените следующие две строки:

```properties
WEATHER_API_ID=ваш ID
WEATHER_API_KEY=ваш KEY
```

Учётные данные внедряются в код через `BuildConfig` (см. `app/build.gradle.kts`) и не попадают в систему контроля версий.

> Можно и без пересборки: просто укажите личные `appid` / `appkey` / адрес API в разделе «Настройки → Учётные данные API (опционально)» в приложении; пользовательская конфигурация имеет приоритет. Если поля пусты, используется встроенный вариант по умолчанию (хранится только в локальном DataStore).

> В проект по умолчанию встроены официальные публичные тестовые учётные данные `88888888 / 88888888`, лимиты запросов которых **общие для всех разработчиков** (в часы пик может возвращаться «слишком частые запросы»). Они предназначены только для разработки и отладки и не подходят для релизных сборок.

## Как изменить цвет темы

Цвета темы централизованно определены в `app/src/main/java/com/jianyi/outfit/ui/theme/Color.kt`:

```kotlin
val MorandiBlue = Color(0xFF6B82A6)   // Измените эту строку, чтобы перекрасить всё приложение (основной цвет светлой темы)
val DarkPrimary = Color(0xFFA7BCDA)   // Основной цвет тёмной темы (сохраняйте достаточный контраст)
```

Также синхронно обновите файл ресурсов `app/src/main/res/values/colors.xml` (на него ссылаются иконка запуска/фон окна) и `drawable/ic_launcher_background.xml` (фон иконки).

Согласно дизайн-спецификации, во всём приложении не более 3 основных цветов:

- 1 цвет темы: синий Моранди `#6B82A6`
- 2 статусных цвета: светло-оранжевый для высокой температуры `#F5A67A`, светло-голубой для низкой `#7EB3D5` (только для подсказок)

## Как изменить правила рекомендаций

Вся логика рекомендаций сосредоточена в `app/src/main/java/com/jianyi/outfit/engine/OutfitRecommendationEngine.kt` — чистая реализация на Kotlin с сопутствующим модулем теста `app/src/test/.../OutfitRecommendationEngineTest.kt`:

- **Температурные диапазоны**: измените `temperatureBucketItems()` и `temperatureBucketRange()`
- **Правила поправок на УФ / ветер / влажность**: измените шаг 3 в `recommend()`
- **Сценарная адаптация** (строгая одежда для работы, быстросохнущая для прогулок, свободная для повседневного): измените `commuteItems()` / `outdoorItems()` / `casualItems()`
- **Смещение по устойчивости к холоду/жаре**: измените `toleranceOffset` (сейчас ±2℃)

После изменений запустите `./gradlew test`, чтобы убедиться, что правила не сломаны.

## API погодных данных

Источник данных: данные Китайского метеорологического управления, предоставляемые apihz.cn (бесплатная регистрация). Обёрнуты три конечных точки текущей погоды и 7-дневный прогноз:

| Конечная точка | Назначение |
|------|------|
| `GET /api/tianqi/tqybip.php` | Автоопределение по IP (первый запуск) |
| `GET /api/tianqi/tqyb.php?sheng=&place=` | Запрос по адресу (поиск города) |
| `GET /api/tianqi/tqybjw1.php?lat=&lon=` | Запрос по координатам (GPS) |
| `GET /api/tianqi/tqyb.php?...&day=7` | 7-дневный прогноз |

- Ответ с `code=200` означает успех, `code=400` — ошибку; причина ошибки содержится в `msg` и показывается пользователю через Snackbar/панель ошибок.
- Погодные данные кэшируются локально на 30 минут и автоматически обновляются по истечении срока; при отсутствии сети используется устаревший кэш как запасной вариант, чтобы приложение оставалось работоспособным.

## Известные особенности

- **Стратегия геолокации (по надёжности)**: выбранный вручную кэшированный город → координаты GPS → запасной вариант IP. Определение по IP опирается на базы IP операторов и может «дрейфовать» между городами (например, показывать Чжаньцзян, находясь в Чжуншане), поэтому используется только как запасной вариант при отсутствии разрешения на геолокацию / Play Services / выключенных сервисах местоположения; в режиме IP рядом с названием города отображается значок Wi-Fi и появляется плашка «Нажмите, чтобы использовать точное GPS-определение».
- **Конечная точка координат использует глобальный источник данных** (`tqybjw1.php`): структура ответа отличается от точек IP/адрес — нет провинции, нет разницы дневной/ночной температуры, нет предупреждений — и **названия городов отображаются в пиньинь** (например, Zhongshan); при отсутствии ощущаемой температуры берётся температура воздуха, а сила ветра пересчитывается из скорости в шкалу Бофорта.
- **Защита от лимитов запросов**: при срабатывании лимитов публичных учётных данных в часы пик слой репозиториев автоматически повторяет запрос один раз после паузы, длительность которой предлагает API (поле `s`); при отсутствии данных на экране показывается карточка с обратным отсчётом (автоповтор выполняется только один раз, затем переключение в ручной режим); при наличии кэшированных данных ситуация понижается до подсказки, и кэш продолжает отображаться; ручное обновление и «использовать точное определение» делят общий 10-секундный троттлинг.
- **УФ-индекс — оценочный**: API не предоставляет поле УФ, поэтому движок оценивает его по «погодному явлению + времени суток» (ясно 7 / переменная облачность 5 / пасмурно 2 / дождь или снег 1, ночью ноль) и отображает в виде «индекс·уровень».
- **GPS зависит от Google Play Services**: на устройствах без GMS геолокация не работает, и приложение предлагает перейти к поиску или определению по IP; работа приложения не блокируется.
- **Ежедневная рассылка** построена на постоянной периодической задаче WorkManager (каждые 24 часа; время рассылки выбирается в настройках и может сдвигаться на несколько минут в режиме экономии заряда); задача сохраняется системой и **автоматически восстанавливается после перезагрузки устройства без повторного открытия приложения** (приёмник загрузки заново выравнивает её по заданному времени); на Android 13+ при первом включении запрашивается разрешение на уведомления.
- **Тёмная тема** следует системе (фон `#121212`, карточки `#1E1E1E`, текст `#E0E0E0`, без чисто чёрного цвета).
