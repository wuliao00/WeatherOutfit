# 「历史上的今天」撰写规范

本规范是起草者与审定者的共用契约：起草者按它写，审定者按它抽查。
可自动判定的条款由 `tools/validate_today_dataset.py` 在每次合片后执行（违反即 FAIL，退出码 1；
另有事件占比、近年条数、体积三项 WARN，只发声不拦截）；
标注「人工」的条款没有可靠的可执行判据，由审定者抽样负责（Task 7 Step 5，spec 10.6）。

数据规模：366 天 × 3 条 = 1098 条；描述全部由本项目自撰，外部源只提供日期事实（spec 3.2）。

## 硬约束（校验脚本自动拦）

- 每日 3 条，不多不少；同一天的 3 条 **年份互不相同**（三条挤在同一年，卡片信息量变单薄）
- 每条一句，14~26 个字符（校验脚本按整句长度计，数字与标点都计入），以「。」结尾
- `type` 只能是 1（事件）/ 2（出生）/ 3（逝世）
- 不写未来年份
- 不保留任何外部源痕迹：`[n]` 引用标记、HTML 尖括号、未解的 `\u` 转义
  —— spec 2.7 的许可前提是「文本全部自撰」，混进这些就是搬运没搬干净的物证

## 用词与表述（人工）

- 只写能被独立查证的事实：主体 + 动作 + 时间/地点/数量
- 不写评价词（"伟大的""著名的""重要的"）、不写程度副词（"非常""极其"）
- 不写仍在争议中的表述；有分歧的选最中性的一种说法
- 不用感叹号；不写"我国""本市"这类以作者立场为中心的指代
- 出生/逝世条目写「X（生卒年/身份）出生」/「X 逝世」形式，不堆砌头衔

## 选题

- 优先：影响面广的 > 与天气/季节/自然有关的 > 科技与文化 > 政治军事
- 近三年（2023~2026）的事件优先入选——源骨架止于 2020，
  这些日子必须自己补，否则卡片会永远停在六年前（spec 2.7）
- 全文 2023 年及以后的事件不少于 60 条（校验脚本按 y ≥ 2023 计数，不足发 WARN，不拦）

## 逐日配额

- 事件(1) ≥ 1 条；若某日实在没有可用事件，允许 2 出生 + 1 逝世，
  并在提交说明里点名这些日期
- 全库事件占比低于 40% 时发 WARN——逐日配额是目标而非硬闸，
  脚本不做逐日 type 强制，靠起草者自觉与审定者抽查
